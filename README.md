# momo-texture-library

Momo Texture Forge 的静态远程图形库。资源目录、ZIP 和缩略图一起发布，可通过图形编辑器订阅。

## 文件结构

- `index.json`：资源ID、版本、下载地址、SHA-256与缩略图地址。
- `resources/`：完整资源 ZIP，含公式或图片及依赖。
- `thumbnails/`：从资源包提取的独立预览图片。
- `index.html`：图库浏览、搜索及下载页面。
- `.nojekyll`：让 GitHub Pages 直接发布静态文件。

## 发布到 GitHub Pages

提交并推送这些文件，在仓库 **Settings → Pages** 中选择 **Deploy from a branch → main → /(root)** 并保存。

部署完成后的图库首页：

```text
https://fgh23387736.github.io/momo-texture-library/
```

在 Momo Texture Forge 的“图形库 → 远程图库”中添加：

```text
https://fgh23387736.github.io/momo-texture-library/index.json
```

以上地址在 Pages 成功部署后生效；首次发布后需验证目录与资源可以正常读取。

## 更新资源

### 使用随包的本地管理器

使用新版桌面 **Chrome 或 Edge** 打开仓库根目录 **[library-manager.html](library-manager.html)**，点击“选择本地图库目录”，选中本仓库文件夹并授予读写权限。无需安装 Node.js、npm、编辑器或启动服务。也可通过HTTPS打开 `manager/index.html`，再选择本地文件夹；不支持的环境会显示明确提示。会记住上次授权目录，权限有效时自动恢复，否则点击“继续使用”授权。“关闭图库”会忘记目录；清理浏览器数据或更换页面来源可能需重选。

管理器支持搜索浏览、导入正式单资源/合集 ZIP（先预览再确认）、编辑目录信息、修改图库名称、批量移出目录和恢复目录快照。元信息修改只影响 `index.json`，不更改原资源包、ID、版本或校验值；重复导入保留当前目录别名和标签。同 ID 同版本内容不同会被拒绝。

管理器**只修改你选择并授权的本地文件夹**，不操作Git、不上传CDN、不保存发布凭据。即使管理页通过线上打开，操作的也是访问者自己的本地目录，不能修改服务器资源。完成整理后，请自行提交并推送，或上传修改后的文件；部署时先上传资源和缩略图，最后更新目录。整个仓库均可发布。

“移出目录”不物理删除ZIP和缩略图，避免旧链接失效。每次目录修改前在当前浏览器保存最多50份恢复快照，不写进仓库；清理浏览器数据、换浏览器或访问来源会失去原快照。重要目录可在“目录恢复”下载JSON备份，并从JSON恢复（校验图库身份和引用资源）。无缩略图资源显示占位符。请避免用其他程序同时修改目录，检测到冲突后请刷新目录；权限失效时点击“继续使用”授权。

管理页是自包含静态HTML，位于根目录及 `manager/index.html`，无需运行时、服务或网络请求；旧Node服务与启动脚本已移除。文件夹读写权限由浏览器控制，请勿禁用安全保护。详情见 [管理器说明](manager/README.md)。

### 使用开发工具命令

从编辑器导出资源 ZIP，然后使用 Momo Texture Forge 提供的打包工具。以下命令在本仓库目录执行，先替换两处路径占位符：

```text
node "<TextureForge工具目录>/build-remote-library.mjs" --input "<导出的资源ZIP路径>" --out "." --name "Momo Texture Library"
```

继续使用同一目录可保留图库身份并合并新资源和更高版本；未涉及的条目与旧资源文件保留。相同ID和版本不可对应不同的资源内容。打包后提交并推送，等待 Pages 完成部署。

缩略图从资源包已有的预览提取；原包没有预览时，当前工具不会自动渲染补图。图库浏览页始终读取最新的 `index.json`，无需逐个手工维护卡片。


“彻底删除”会移除所选目录条目并删除当前引用的 ZIP 和缩略图，共用文件保留；历史版本和此前移出目录的文件不自动清理。删除前需确认，旧项目下载可能受影响，目录快照/JSON 不能恢复已删除文件。先保存目录再清理文件；清理失败会列出未删除路径，需检查权限后手动清理。本地删除要自行发布后才影响远程，浏览器已有缓存不受本地删除直接影响。
